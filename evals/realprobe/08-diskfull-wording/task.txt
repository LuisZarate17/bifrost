In apps/hugin/src/print.rs, `report_of` turns a finished check into a `CheckReport`. A check that was killed because its drive was nearly full (`Ended::DiskFull`) is reported with `not_run(argv, "stopped because the disk was nearly full")`. That reads wrong: the text says "The check was not run: stopped because the disk was nearly full" and "check: `cargo test` was not run: stopped because...", and the JSON puts the reason in `check.not_run`, but the check did run and was stopped part way.

Make a disk-full stop read as stopped, and keep everything else as it is:

1. Add a field `pub stopped: Option<String>` to `CheckReport`: why a check that did run was stopped before it finished. `report_of` with `Ended::DiskFull` returns a `CheckReport` with `stopped` set to exactly `stopped because the disk was nearly full`, `not_run` None, `passed` None, `timed_out` false, and `seconds` the check's elapsed time. Every other `CheckReport` has `stopped` None.
2. A check with `stopped` set is unverified, like one that timed out or was not run: the report stays partial, its status is `Partial` and the exit code is 3.
3. In the text, the first line of a partial proposal says `The check was stopped because the disk was nearly full` (the reason follows "The check was "), and the `check:` line says ``check: `cargo test` was stopped because the disk was nearly full``. Neither says "not run".
4. In the JSON, `check` gets a new field `stopped` (the reason, or null), placed directly after `not_run`; for a disk-full stop `not_run` is null and `stopped` is the reason.

The text and JSON for a check that was not run, that timed out or that failed must not change. Update the existing tests that pin the old wording and the exact JSON field list, and add a test that a disk-full stop is stopped in the text and the JSON and still partial with exit 3. Change nothing else.
