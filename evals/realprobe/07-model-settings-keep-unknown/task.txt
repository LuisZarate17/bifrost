In crates/bifrost-core/src/config.rs, `Config` keeps keys it does not know at the top level of config.json (the `extra` field), so a newer build's settings or a person's own notes survive a load and a save. The same is not true one level down: `lenient_model_settings` rebuilds every `model_settings` entry from `ModelSettings`, which only has `think`, so any other key inside an entry, for example `{"gpt-oss:20b": {"think": "high", "temperature": 0.3}}`, is lost on the next save. Change that: keys inside a `model_settings` entry that this build does not know are kept as they were (any JSON value) through `load_from` followed by `save_to`, written beside `think` in the same entry.

Everything else about reading an entry stays: an entry that is not an object is still dropped; a `think` that is not off, low, medium or high (in any case) is still unset, and it is not kept as an unknown key, so it is not written back; a valid `think` is written once, in lower case, and not again as an unknown key. `Config::settings_for` and the `think` field keep working as they do. Code that builds a `ModelSettings` by hand will need updating. Add tests in the existing `mod tests` for the round trip, and for the bad `think` and the valid `think` beside an unknown key. Change nothing else.
