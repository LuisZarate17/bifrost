In apps/hugin/src/main.rs, `parse()` takes the word right after `--ask` as the question, whatever it is. So `hugin --ask --json` asks the model the question "--json" and `hugin --ask --json "where is the parser?"` fails later with an unrelated "unknown argument" error. Change `--ask` so that a word that starts with `--` right after it is not a question: parsing returns `Err` with a message that contains `--ask needs a question` (the existing message for `--ask` with nothing after it, `--ask needs a question, or - to read it from standard input`, is fine to reuse), and `hugin` exits 2 as it does for every command line it cannot read.

Everything else about `--ask` stays: a single `-` is still the question read from standard input; a word that starts with only one dash, such as `-5 degrees: why?` or `-x`, is still a question; an empty question is still accepted by `parse` (it is refused later, in `ask::run`); and `-p` is not changed at all, so `-p --json` still means the task "--json". Keep the check in a small function in main.rs, and add test assertions to the existing `ask_refuses_what_it_cannot_do_and_says_so` test in `mod tests_main` for a flag after `--ask` and for a one-dash question. Change nothing else.
