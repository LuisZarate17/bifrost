In crates/bifrost-core/src/config.rs, an empty check command is stored as if it were a check. `Config::set_check(root, Some(vec![]))` inserts an entry with an empty list, and `lenient_checks`, which reads `checks` from the file, keeps an entry like `"C:\\x": []`, so it is written back on every save even though `check_for` already ignores it. An empty command is no command.

Change both halves. `set_check(root, Some(vec![]))` must clear the folder's check exactly as `set_check(root, None)` does, including an existing entry that differs only in case. `lenient_checks` must drop an entry whose list is empty, so that after a load there is no entry for that folder and the next save does not write it back. Entries with at least one word are read and set as before, and an entry that is not a list of strings is still dropped as before. Update the doc comments of the two functions to say so, and add tests in the existing `mod tests` for setting an empty check and for loading one. Change nothing else.
