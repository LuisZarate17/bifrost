In crates/bench/src/bin/toolprobe.rs, `main` reads its flags with `args.iter().position(...)` and `args.iter().any(...)` and ignores everything it does not recognise, so a misspelt flag (`--recovr`) is silently dropped and the probe runs with the defaults. It also has no `--help`. Add both, as a small piece at the very start of `main`, before the config is read or anything else happens.

The flags toolprobe takes are: `--model` and `--think`, each followed by a value; and `--recover`, which stands alone. Add `--help` (also `-h`), which stands alone too.

1. `--help` or `-h` prints a short usage to standard output and exits with code 0. The usage names every flag above, `--help` included, with a few words on each. Nothing else runs.
2. Any argument that starts with `-` and is not one of those flags, and is not the value of a flag before it, prints `unknown flag: <the argument, whole>` and then the usage to standard error and exits with code 2. Nothing else runs. So `--bogus`, `-z` and `--model=x` (the `=` form is not supported) are all unknown, and flags are matched exactly (`--MODEL` is unknown).
3. The word right after a flag that takes a value is that flag's value, whatever it starts with: `--model -x` is not rejected, and neither is `--model --bogus`. A flag that stands alone does not take a value: in `--recover -x`, `-x` is unknown. A value flag with nothing after it at the very end is not an unknown flag. Words that do not start with `-` and are not a value are not checked.

Put the check in a function with exactly this signature, and use it from `main`: `fn unknown_flag(args: &[String]) -> Option<String>`, which returns the first unknown argument, or `None` if there is none (`--help` and `-h` are known). Keep the flag lists and the usage text as constants or functions in the same file. The file has no tests yet: add a `#[cfg(test)] mod tests` at the end of it with unit tests for `unknown_flag`. Change nothing else.
