In apps/hugin/src/print.rs, `parse_check` turns the text of `--check` into the program and its arguments. It runs the program directly, not through a shell, and on Windows `npm` is a batch file, so the function spells it `npm.cmd` (matching `npm` in any case: `NPM` also becomes `npm.cmd`). `npx`, `pnpm` and `yarn` are batch files on Windows too and fail the same way. Do the same for them: when the first word of the check, ignoring case, is exactly `npx`, `pnpm` or `yarn`, it becomes `npx.cmd`, `pnpm.cmd` or `yarn.cmd` (always lower case, like `npm.cmd`). Only the first word, the program, is changed; arguments are left alone, and a program that merely starts like one of the names (`npxx`) or is already spelled with an extension (`npm.cmd`) is not touched. The signature stays `pub fn parse_check(text: &str) -> Result<Vec<String>, String>`. Update the doc comment of `parse_check`, which today says only `npm` is spelled `npm.cmd`, to list the four. Add assertions for the three new names (including a mixed-case spelling, and a lookalike that is not changed) next to the existing `npm` assertions in `apps/hugin/src/print_tests.rs`. Change nothing else.
